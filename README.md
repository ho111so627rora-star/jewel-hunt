# ジュエルハント everyday

スマホ・PCのブラウザで遊べる、10ターンの宝石争奪ゲーム。Next.js / React / TypeScript / Three.jsで実装しています。

## 立体のゲーム卓

- 4人で囲む木製の卓を、自分の席から見ます。プレイヤーごとにカメラが回転し、常に自分のカップが手前に来ます。
- 左右のカップを選び、サイコロ・泥棒のフィギュア・ダイヤの採掘権・薬瓶を入れます。「カップを伏せる」で確定します。
- 全員がそろうと共通の公開時刻までカウントダウンし、8個のカップを持ち上げます。公開時刻まではAPIも他人の選択を返しません。
- 採掘時には中央の宝箱が開き、実際に引いた色のサイコロが自分の席に移動します。盗み・衝突・宝石獲得も卓上で移動します。
- 宝石マーケット、コレクション、記録は卓上のボタンから確認できます。「卓を見渡す」で俯瞰視点に切り替えられます。
- 対決するカップ同士を金色（自分の左 ↔ 相手の右）と水色（自分の右 ↔ 相手の左）のラインで結びます。ターンが変わるとラインも切り替わります。
- 各席の名札には特殊駒の使用数を表示します。名札または「みんなの持ち物」をタップすると、各人の宝石を色・数字ごとに確認でき、泥棒・劇薬・採掘権の使用数と残りも見られます。不発も使用数に含み、公開前の選択は反映しません。
- 3Dが利用できない端末は軽量表示に切り替わります。描画は約30fps、ピクセル比は最大1.6に制限し、背景タブでは停止します。動きを減らす端末設定にも対応します。

## CPUの判断

CPUは公開済みの手の履歴と所持駒から左右別の傾向を見積もり、得点、盗難リスク、全員とのバッティング、4色ボーナス、残りターンと採掘の価値を比較します。劇薬では4色コンプリートを崩す効果も考慮します。現在の未公開の選択や、他CPUが確定した手は読みません。

固定シード・席交代で旧CPU3人との120試合を比較するテストを用意しています。比較テストは src/game/cpu.test.ts にあります。

## 起動

Node.js 22以上をインストールし、リポジトリを取得します。

```sh
git clone https://github.com/ho111so627rora-star/jewel-hunt.git
cd jewel-hunt
npm ci
npm run build
npm start
```

ブラウザで http://localhost:3000 を開きます。開発時は `npm run dev` を使います。対戦データは初回実行時に `.data/rooms/` に作成され、GitHubには保存しません。

この作業環境では `start-game.cmd` をダブルクリックすると起動できます。起動中はウィンドウを開いたままにしてください。本番ビルドが存在する場合は本番サーバーを使います。

PowerShellの場合は次を実行します。

```powershell
cd C:\jewel-hunt
.\start-game.ps1
```

PCで http://localhost:3000 を開いてください。通常のNode.js環境では `npm install` → `npm run dev` でも起動できます（Node.js 22以上）。

スマホはPCと同じWi-Fiにつなぎ、`http://PCのIPv4アドレス:3000` を開きます。PCのアドレスは `ipconfig` で確認できます。Windowsファイアウォールで接続が制限される場合は、Node.jsへのプライベートネットワーク接続を許可してください。

## 遊ぶ

1. 名前と人間の人数を選び、「ハントを始める」を押します。
2. 2人以上の場合、ほかの人は別端末・別ブラウザで「ルームに参加」から6文字のコードを入力します。
3. 好きな色を選び、ホストが開始します。
4. 手前の左右のカップを選んで駒を入れます。宝石は上に向ける目も選び、「カップを伏せる」で決定します。
5. 全員の決定後に一斉公開。結果を確認し、全員が次のターンに進みます。
6. 10ターン後、4色コンプリートの5点ボーナスを含む最終順位を表示します。

| 人間 | CPU | 合計 |
|---|---|---|
| 1人 | 3人 | 4人 |
| 2人 | 2人 | 4人 |
| 3人 | 1人 | 4人 |
| 4人 | 0人 | 4人 |

各参加者に別のブラウザ保存領域が必要です。同じブラウザの複数タブは同じ参加情報を共有します。画面を再読み込みすると、保存された参加情報から対戦に復帰します。

## 実装と保存

- `src/game/`：UIやデータベースに依存しないゲームエンジンと単体テスト。
- `src/server/rooms.ts`：ルーム、参加者認証、CPU、秘密選択、ターン更新。
- `src/app/api/rooms/route.ts`：選択などの意思決定のみを受け取り、サーバーで判定。
- `src/components/table/`：立体モデル、ライティング、席ごとのカメラ、駒の移動、手元の操作。
- `.data/rooms/`：ルーム状態をJSONファイルに保存。サーバー再起動後も復帰できます。

CPUは人間の未公開の選択を参照しません。公開前のAPI応答には、要求した本人以外の選択を含めません。状態の更新は約0.55秒間隔のポーリングで、共通のサーバー時刻を使います。実際の表示タイミングには通信遅延の差が生じます。

要件書で明示されていない「得点できなかったゾロ目の宝石」は袋に戻します。手持ちが2個未満なら残りを出し、空ならパスします。通常の宝石は劇薬・採掘に対しても自分が獲得します。劇薬はそのターン開始時点の獲得済み宝石を対象とします。

## 公開運用について

現在はこのPCまたは永続ディスクを持つ単一Node.jsサーバーで動作します。インターネット上へのデプロイは行っていません。Supabase、複数サーバー間の共有DB、アカウント登録、ランキングは未実装です。サーバーレス環境への公開には永続DBへの置き換えが必要です。

### 公開後の確認
- カップ公開後は、全員の左右の駒を表示したまま停止します。「確認した · 得点と効果を実行」を人間プレイヤー全員が押すと、得点・泥棒・採掘などを処理します。再読み込みしても確認待ちを維持します。
- 卓の下の一覧に、各プレイヤーの得点となる宝石の色・数字・個数を常時表示します。採掘結果は獲得したサイコロの色を図示します（出目は次に使うときに選びます）。

### 対面するカップの対応
左右は各プレイヤー自身から見た向きです。自分の左カップは対戦相手の右カップ、自分の右カップは相手の左カップと対決します。正面・右隣・左隣のどの席が対戦相手でも同じ対応です。卓上の金色の線は自分の左と相手の右、水色の線は自分の右と相手の左を結びます。CPUもこの対応で相手の公開履歴を予測します。

### 色と数字の重複
自分の左右が同じ色・同じ数字の場合だけゾロ目となり、自分では得点化できません。赤1＋青1のように色が異なる場合は、同じ数字でもそれぞれ得点になります。異色の同数はバッティング判定から除外しません。

### 思考時間
各ターンの駒の選択は全員共通で60秒です。残り時間を表示し、残り10秒から強調します。期限はサーバーが保持し、再読み込みでも延長されません。期限後の最初のポーリングまたは操作で、未確定のプレイヤーだけCPUが合法手を選んで確定します。選択済みの駒は維持します。公開後の確認待ちに時間制限はありません。

### 採掘演出と進行ボタン
採掘は宝箱を混ぜる演出の後、獲得したサイコロを表示します。演出中は採掘の結果・記録・手持ちへの追加表示を待ち、結果表示後に次へ進めます。動きを減らす設定では演出を短縮します。確認・次ターン・劇薬の選択は卓の上のコンパクトな操作バーに配置し、スクロールしても画面上端に残ります。

### 採掘の秘密情報
採掘したサイコロの色とガチャ演出は本人だけに表示します。他プレイヤーには採掘した事実のみ公開します。APIは相手の未使用宝石、相手の採掘イベント、採掘袋の色別内訳を送信せず、記録も色を伏せます。得点化済みの宝石と公開したカップは全員に見えます。CPUも相手の秘密の所持色や採掘袋の内訳を参照せず、公開情報から予測します。

### 劇薬での獲得枠の再開放
劇薬で通常の獲得済み宝石を失わせたら、その色・数字のマーケット枠も空け、全員が再び選べるようにします。完売後に追加獲得した1点は通常の番号枠を占有していないため、失っても別の宝石の枠を空けません。完売中に選んだ追加1点は、同じターンの劇薬で枠が空いても追加1点として処理します。
